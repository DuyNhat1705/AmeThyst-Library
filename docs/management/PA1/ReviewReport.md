## 2. Problems
- **In Building Framework:**
  - Lack of knowledge about React NextJs and ExpressJs initially
  - Time consuming in learning and exploring through document and video these frameworks before set up
- **In Writing Application Survey:**
  - Difficulties in filtering out the similar apps for survey
  - No account authorization, requiring to be a student of corresponding university or organization, to access all functions for testing
  - These authorized functions have tutorial documents, but they are quite complex to understand the functions without practical using
  - The first proposed version of application survey is unstructured and contains many technical terms which cause difficult to understand and imagine the description. It needs the clear, rigorous outline and a decrease in using technial terms to become more understandable.
- **In UI/UX Design:**
  - Time consuming in desiging on self on Figma
  - Using Stich from Google to generate base of GUI before continuing with Figma, but the result from Stich do not satisfy the expectation and idea.
  - Lack of animation for an interesting GUI
  - Wasting tokens when generating GUI using the free agent in student package
- **In Collecting Data:**
  - Too large amount of data which exceeds the available computer storage and databse capacity in free version
  - Data lacks of neccesary fields for our product
  - Difficulties in deciding the way database store the data and select necessary data from initial raw data for using
## 3. What can be done differently in next sprint to improve
- To avoid unstructured drafts and over using technical terms like in the version of application survey, the team member who is assigned to the corresponding document tasks should plan the outline and proposed to team leader before writing. Besides that, team members should cross-review documents and give feedback for the assignees to fix in time.
- Instead of spending too much time solely reading complex tutorial documents about the function, the team members can use AI to summary it and ask more detailing about certain function or usecase to let the AI explain for them.
- To tackle storage limitation, the team must filter the raw data and define the database schema before starting to store these into the database.
- The team should dedicate time to research and try to implement basic animations to make the GUI more engaging.
- Understanding the code and fixing minor bugs manually to reduce unnecessary token consumption when using AI agents.
## 4. What lessons we could learn
- Initial decribing documents like application surveys or proposals must be well-structured and use balanced language to better understand and set up for coding later more easily.
- It is important to evaluate data avaibility, filter out raw data, and define schema limitations early on.
- Aligning the UI/UX foundation, database schemas, and framework setups before jumping into functional coding is excellent practice helping reduce name confliction and poor code classification, modulization among team members.
